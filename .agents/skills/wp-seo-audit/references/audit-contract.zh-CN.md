# Athletik SEO 审计契约（中文阅读版）

> 本文件是 `audit-contract.md` 的简体中文阅读版。实际执行以英文文件为准。

广泛或多来源审计，以及把问题定为 Critical 或 Warning 前，读取本参考。

## 分类

技术严重度、业务优先级和证据置信度必须分开。

### 严重度

- `Critical`：已确认的生产问题，对重要 URL 集合的抓取、索引、canonical 归属、渲染或访问造成阻断或严重破坏。数据缺失和可选增强项绝不能定为 Critical。
- `Warning`：已确认的缺陷或实质风险，会影响发现、理解、体验或转化，但没有形成全站阻断。
- `Info`：观察项、增强机会、刻意设置的控制项，或需要更多证据的问题。

### 业务优先级

- `P0`：正在发生且实质影响业务或索引，需要所有者立即关注。
- `P1`：依赖条件满足后，具有较高预期收益或风险降低价值。
- `P2`：影响范围有限或工作量中等，但值得实施的改进。
- `P3`：监控、记录，或只在重新开启条件出现时复核。

严重度不能单独决定优先级。主商业模板上的 Warning，可能比刻意不索引的低价值 URL 上更严重的问题优先级更高。

### 置信度

- `Confirmed`：由权威渲染结果、源代码、第一方数据或可复现工具证据直接观察到。
- `Probable`：多个一致信号支持推断，但仍缺一个重要验证步骤。
- `Unverified`：尚不能支持修复的假设或第三方指示。

## 数据状态

使用一个或多个精确状态：`complete`、`partial`、`sampled`、`capped`、`filtered`、`skipped` 或 `unavailable`，并说明受影响的来源和范围。这些状态都不等于零。

## Finding 结构

每项 Critical 或 Warning 必须包括：

- 稳定 ID 和精确标题；
- 类型：`fix` 或 `review`；
- 严重度、业务优先级和置信度；
- 受影响的 URL、模板或 segment；
- 证据来源和数据状态；
- 观察到的证据，与推断分开；
- 可证伪条件；
- 最小建议操作；
- 依赖项或所需所有者决策；
- 验证方法和复核周期；
- 允许结果。

允许结果：

- 修复类：`fixed`、`deferred`、`not-needed`；
- 复核类：`changed`、`no-change`、`deferred`。

`Unverified` 项通常保持为 review；通过验证条件前不能转成 fix。

## 重复与冲突处理

- 保留每个原始工具 finding ID 和 inventory 处置记录。
- 相同根因的问题可以合并，但不能删除来源 ID。
- 重复项标记为 `duplicate`，并指向归属 finding。
- 来源冲突时标记为 `contradicted`，展示双方观察结果，说明本问题应以哪个来源为权威，并定义下一验证步骤。
- 不得因为多个工具重复同一 heuristic 就提高严重度。
- 项目真值或直接证据证伪工具 finding 时，可以结束为 `not-needed` 或 `no-change`。

## 失败与停止规则

| 条件 | 必须采取的响应 |
|---|---|
| CLI 或必要工具缺失 | 报告 blocker；未经授权不得安装。 |
| 认证不可用 | 继续使用不需要认证的来源；把缺失数据集标记为 unavailable。 |
| DNS、超时或 provider 限流 | 同一来源最多重试一次，然后停止该来源。 |
| 一个结构化报告失败 | 保留成功证据；说明失败范围；不得声称审计完整。 |
| 结果 partial、capped 或分页 | 成本合理时取回剩余页面，否则说明确切的未复核范围。 |
| 源代码与渲染输出不一致 | 保留双方证据；验证环境、缓存和渲染后再建议修改。 |
| 数据无法区分两种解释 | 返回 review，并给出能证伪每种解释的测试。 |

不得进入重复 fallback 循环，也不能用未标记的第三方估算代替缺失的第一方数据。

## 覆盖模式

选择并披露一种模式：

- `full`：复核范围内每个 URL 和 inventory 行；
- `stratified`：按页面类型、模板、索引状态和业务重要性抽取代表 URL，同时对完整可用集合统计状态/canonical inventory；
- `targeted`：只复核明确指定的 URL 或问题集合。

当前 Athletik 小型网站在可行时使用 full。只有 URL 数量或重复模式使全量内容复核不成比例时，才切换到 stratified。必须报告样本选择、数量、排除模式和重新开启条件；抽样结果不得称为全站 all-clear。

## 输出顺序

1. 范围、环境、日期、覆盖模式和证据来源；
2. Critical、Warning、Info；
3. 已通过的检查；
4. URL 和重定向说明；
5. 按业务收益、风险、依赖项和工作量排序的行动；
6. 证据缺口、延期事项和重新开启条件；
7. finding 与 inventory 对账总数。

除非用户要求，不得创建报告文件、HTML 成品、ticket 或外部提交。不得把结论压缩成单一 0–100 分数。
